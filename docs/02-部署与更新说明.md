## 一、敏感信息放在哪里（只说明位置，不公开内容与加密方式）

| 信息 | 存放位置 |
|---|---|
| 统计 token、未来可能用到的密钥 | GitHub 仓库 → Settings → Secrets and variables → Actions → **New repository secret**（名称见下） |
| 本地调试用的敏感配置 | 本机 `secrets/` 目录或 `.env` 文件（已在 `.gitignore` 中忽略，永远不会提交） |
| 公开可提交的配置 | `content/config.ini`（只放公开信息，如站点标题、giscus 的 repo id） |

当前不涉及服务器 IP、数据库密码等服务器类敏感信息，因此仓库可以**完全公开**。

已约定的 Secret 名称（需要时再实际填写内容，不要把内容写进任何提交）：

- `SITE_ANALYTICS_TOKEN`：访问统计 token（生成脚本从环境变量读取，不写入仓库）

> 说明：giscus 的 `repo_id` / `category_id` 是公开标识符（浏览器端必须读取），可以写在 `content/config.ini`；**不要**在这里放任何私钥、密码、服务器 IP。

## 二、首次接入 GitHub Actions（只需一次）

1. 确认仓库是公开仓库：`github.com/ShakeTTK/music` → Settings → General → 最下方 Visibility 为 Public。
2. 本目录**已经完成**本地 Git 初始化与首次提交（`29550fb`），并已添加远端。你只需要确认远端并推送：

```powershell
cd D:\AIMUSIC\MyMusicCatalog.v2
git remote -v          # 应显示 origin  https://github.com/ShakeTTK/music.git
git push -u origin main
```

> 首次推送约 250 MB，网络慢时可能要几分钟到几十分钟。如果换了机器或重新克隆，才需要重新执行 `git init` / `git remote add origin ...`。
> 推送完成后 Actions 会自动构建；但请先把第 3 步的 Pages Source 切好（顺序见下方提示）。

3. 打开 GitHub 仓库 → **Settings → Pages** → Build and deployment → Source 选择 **GitHub Actions**。
4. 打开 **Actions** 页面，应该能看到「构建并部署站点」工作流；等它跑完（约 2–5 分钟）。
5. 访问 https://shakettk.github.io/music/ 验证。

> **顺序提示**：切换 Pages Source 到第一次 Actions 部署完成之间，线上可能短暂出现 404，这是正常现象；也可先推送源码，再立刻切换 Source。

> ⚠️ 推送会替换远端仓库原有的构建产物。旧版站点已完整备份在 `F:\MyMusicCatalog-backup-2026-10-22`，旧目录 `D:\AIMUSIC\MyMusicCatalog` 也仍在。

## 三、日常更新流程

```
改 content/ 里的文件（歌词、日期、关于页、图片……）
        ↓
双击 scripts\update.bat
        ↓
本地自动构建校验（失败会停下来，不会推送坏版本）
        ↓
自动 git commit + git push
        ↓
GitHub Actions 云端构建 → 自动发布
        ↓
1-3 分钟后线上生效
```

也可以在 GitHub 网页手动触发：Actions → 构建并部署站点 → Run workflow。

## 四、评论窗口（giscus）配置

评论使用 GitHub Discussions 承载，评论会显示时间，不需要额外服务器。

1. 仓库 → Settings → General → Features → 勾选 **Discussions**。
2. 打开 https://github.com/apps/giscus 安装到该仓库（只授权需要的权限）。
3. 打开 https://giscus.app/zh-CN ，填入仓库 `ShakeTTK/music`，选择 Discussion 分类（建议新建 `Comments`），
   页面会给出 `data-repo-id` 和 `data-category-id`。
4. 把两个 ID 填到 `content/config.ini`：

```ini
[comments]
enabled = true
repo = ShakeTTK/music
repo_id = R_xxxxxxxx
category = Comments
category_id = DIC_xxxxxxxx
```

5. 推送更新即可。未填 ID 时评论按钮会自动隐藏，不影响站点。

> 注意：访客留言需要 GitHub 账号登录（giscus 的限制）。如果以后想支持匿名留言，可以换成 Waline/Twikoo 等方案，只需替换 `scripts/assets/comments.js` 里的加载逻辑，其它模块不受影响。

## 五、访问统计配置（低调、不显示）

以 Cloudflare Web Analytics 为例：

1. Cloudflare 控制台 → Analytics → Web Analytics → 添加站点 `shakettk.github.io`（或你的域名），获得 token。
2. GitHub 仓库 → Settings → Secrets and variables → Actions → 新建 Secret：`SITE_ANALYTICS_TOKEN`，值是 token。
3. `content/config.ini` 里设置：

```ini
[analytics]
enabled = true
provider = cloudflare
token =
```

token 留空即可，构建时会从 Secret 注入（不会出现在仓库里）。
页面不会显示访问量，数据在 Cloudflare 后台查看。

> 也可以换成 GoatCounter：`provider = goatcounter`，token 填 GoatCounter 的站点代码。

## 六、嵌入播放器

`content/config.ini` 中 `[embed] enabled = true` 时：

- 每个作品页会出现「嵌入」入口，进入后用 **APlayer**（MIT 开源播放器）承载的深色嵌入播放器，带封面、标题、进度条、音量与循环控制；
- 复制页面给出的 iframe 代码即可嵌入到别的网页，iframe 高度已同步为 132px；
- 嵌入页不加载水波效果和评论按钮，保持轻量；
- 实现位置：`scripts/postprocess.py` 的 `upgrade_embed_player` 步骤 + `scripts/assets/aplayer/` 资源；
- 如果这一步失败（例如 APlayer 文件缺失），会自动保留 Faircamp 原生嵌入页，站点不受影响。

关闭 `[embed] enabled` 则所有嵌入入口消失。

## 七、模块化与故障隔离

- 内容生成阶段：每个模块独立运行，某个模块出错只记警告，构建继续（详见 `logs/generate-report.txt`）。
- 构建后处理（订阅源修复）：在 Actions 里标记为 `continue-on-error`，失败不影响部署。
- 本地构建：`scripts/build_local.py` 分三步执行，后处理失败只告警。
- 部署：GitHub Pages 部署是原子操作；构建失败时线上保持旧版本不变。
- 回退：`git revert` 上一次提交即可；或从 `F:\MyMusicCatalog-backup-2026-10-22` 恢复旧版。
